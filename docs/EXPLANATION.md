# Подробное объяснение проекта

## Тема 1. Financial QA

Модель получает два поля: вопрос и контекст. Она не ищет данные в интернете и не подключается к базе автоматически. Она извлекает фрагмент ответа из переданного контекста.

Цепочка обработки:

1. Вопрос и документ токенизируются.
2. Transformer вычисляет контекстные представления токенов.
3. Две выходные головы оценивают начало и конец ответа.
4. Pipeline выбирает наиболее вероятный фрагмент.
5. API возвращает ответ, confidence и позиции в исходном тексте.

Модель по умолчанию — `deepset/roberta-base-squad2`. Для реальной оценки подайте ей реальные контексты из SECQUE или SEC filings и сравните результат с эталонным ответом.

Ограничение: длинный 10-K нужно разбивать на части, так как модель имеет ограниченный размер входа.

## Тема 2. Financial Literacy

Модель использует детерминированные правила:

- резервный фонд — до 2.5 баллов;
- процент свободного дохода — до 2 баллов;
- отношение долга к доходу — до 2 баллов;
- бюджетирование — до 1.5 балла;
- инвестиционные знания — 0.5 демонстрационного балла;
- страхование — до 1 балла.

Рассчитываются:

```text
savings_rate = (income - expenses) / income * 100
DTI = debt / income * 100
```

По score, DTI и наличию резервного фонда определяется уровень риска. Затем создаются рекомендации с приоритетами.

## FINRA

Опросник FINRA используется как источник структуры вопросов. Поскольку приложенный PDF не содержит заполненных ответов респондентов, парсер принимает ответы отдельно в виде словаря, например:

```python
responses = {"A3a": 35, "A8": 5, "J2": 1, "J4": 1}
```

Для статистически корректного исследования нужно использовать таблицу ответов и codebook конкретной версии NFCS. В коде маппинг income и правильные ответы M1–M6 находятся в отдельных словарях и должны быть сверены с официальной документацией.
